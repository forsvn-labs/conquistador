This is the recommended option. You need Node 22.18 or later and a supported agent, signed in.

```sh
npx @forsvn/conquistador@latest
# or: bunx @forsvn/conquistador, pnpm dlx @forsvn/conquistador
```

The installer shows the agents it found, already chosen. Keep that set or change it. Then choose the scope and the hooks, review, and install. The last screen shows what to type in each agent. The terminal only installs Conquistador; you do the work in the agent.

## Plugin or skills only

| Agents | What they get |
|---|---|
| Claude Code, Codex, Cursor, GitHub Copilot CLI, Grok CLI | The **plugin** in a global install: the `conquistador` skill, the hooks, and the local MCP server. |
| Gemini CLI, OpenCode, Pi, Hermes Agent, Antigravity CLI, Kiro CLI, Mistral Vibe, Qoder, Rovo Dev, Trae, Trae CN | The **skill folder** only. These agents have no plugin manager, so there are no hooks and no MCP server. |
| Every agent, in a project install | The **skill folder** only, in the project. |

The plugin contains:

- The `conquistador` skill with its commands and plays.
- The MCP server `conquistador`. See [MCP tools](/reference/mcp-tools).
- Hooks for Claude Code, Codex, and Cursor. The prompt hook adds the must-read list to marketing prompts. The stop hook sends the agent back once if it skipped those files. The check hook runs the [copy check](/check) after the agent edits a marketing file.

## Scope

- **Global** installs for all projects. Agents with a plugin manager get the plugin.
- **Project** copies the skill into this project's skill folder. Commit the folder to share it with your team. A project install has no hooks and no MCP server.

With `--yes`, the default scope is global. When the project already has a copy, the default is project.

## Notes for each agent

- Codex asks once to trust the hooks. Type `/hooks` to trust them.
- Pi, Hermes, and Mistral Vibe load project skills only after you trust the project folder.
- The global plugin copy is `~/.conquistador/plugin` (`CONQUISTADOR_HOME/plugin` when you set it). Agents with a plugin manager read it. Do not save your own work in it.
- After the install, start a new agent session. In Cursor, reload the window.

## Install from inside Claude Code

```text
/plugin marketplace add forsvn-labs/conquistador
/plugin install conquistador@conquistador
```

## Install an exact version

```sh
npm install -g @forsvn/conquistador@0.5.0
npm install -g --ignore-scripts --install-links git+https://github.com/forsvn-labs/conquistador.git#v0.5.0
```

`--ignore-scripts` skips npm lifecycle scripts. `--install-links` copies the checkout out of the temporary storage of npm.

## Turn the hooks off or on

- `conquistador hooks off`, or `/conquistador hooks off` in your agent. `conquistador hooks on`
  turns them back on, and `conquistador hooks status` shows the state and what set it.
- `--no-hooks` at install. This writes `{"hooks": false}` to `~/.conquistador/config.json`.
- `CONQUISTADOR_HOOKS=off` in your environment. It wins over the setting.

Each one turns off the prompt, stop, and check hooks, for every agent, from the next prompt.

What each agent's hooks can do:

| Agent | Playbook list on marketing prompts | Copy check after each edit | Read check before the answer ends |
|---|---|---|---|
| Claude Code, Codex | Yes | Yes | Yes |
| Cursor | At session start | Yes | Yes |
| GitHub Copilot CLI | Yes, and at session start | Yes | No |
| Grok CLI | No: Grok drops prompt-hook output; it gets the `conquistador_brief` MCP tool | Yes | No |

The read check is off where the agent's transcript format is not verified yet. The skill still lists the playbooks for each command, so the agent can find them without hooks.
