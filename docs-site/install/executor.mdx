[Executor](https://executor.sh/docs) connects agents to tools and services. Its current setup uses
apps, reusable accounts, and one MCP endpoint for your agent.

## Current Executor flow

1. Add an app or MCP server in Executor.
2. Connect the app's accounts in Executor. Keep provider credentials there.
3. Use **Connect an agent** to configure your coding agent with the Executor MCP endpoint.
4. Sign in through the browser and choose the connection's organization and access scope.
5. Reconnect your agent, read the app's skills, discover tools, inspect their schemas, and call
   the tools you need. Answer approvals where you configured them.

Follow [Executor's client setup](https://executor.sh/docs/mcp-clients),
[MCP discovery](https://executor.sh/docs/mcp), and
[approval guidance](https://executor.sh/docs/concepts/tools-and-approvals).

## Install Conquistador alone

Import `https://mcp.forsvn.com/mcp` through **Connect a service**, then complete OAuth.
Alternatively, import your own public HTTPS deployment. Current MCP import supports
OAuth and no-auth servers; an API-key-only server needs a separate app setup.

For the managed, version-aware installer:

```sh
npx conquistador@latest mcp install --executor
```

Review the plan before applying it. It selects only Executor, without installing
coding-agent plugins or desktop connections. Executor 2 uses the existing owned-app
adapter with the configured connection; Executor 1 uses its legacy source adapter.
These adapters have local contract coverage, which does not establish live acceptance.

The hosted deployment and authentication still need verification. Check the
[current status](https://github.com/forsvn-labs/conquistador/blob/main/STATUS.md)
before relying on the public endpoint. After connecting, discover Conquistador's
tools and call `conquistador_methods` and `conquistador_brief`.

Do not also register direct MCP in the same agent if Executor already supplies these tools.
The legacy `conquistador connect` capability checker does not establish Executor 2
provider readiness; use Executor's own discovery and account flow.
