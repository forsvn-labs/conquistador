[Executor](https://executor.sh/docs) connects agents to tools and services. Its current setup uses
apps, reusable accounts, and one MCP endpoint for your agent.

## Current Executor flow

1. Add an app or MCP server in Executor.
2. Connect the app's accounts in Executor. Keep provider credentials there.
3. Use **Connect an agent** to configure your coding agent with the Executor MCP endpoint.
4. Sign in through the browser and choose the connection's organization and access scope.
5. Reconnect your agent, read the app's skills, discover tools, inspect their schemas, and call
   the tools you need. Answer approvals where you configured them.

Follow [Executor's client setup](https://executor.sh/docs/mcp-clients),
[MCP discovery](https://executor.sh/docs/mcp), and
[approval guidance](https://executor.sh/docs/concepts/tools-and-approvals).

<Note>
  The automatic Conquistador source adapter below uses Executor 1 commands. On Executor 2 the
  installer shows a setup handoff and leaves the source unverified. Native v2 app installation
  and the legacy readiness CLI have not passed live compatibility checks.
</Note>

| Use | What it does | Version |
|---|---|---|
| Conquistador as an Executor 1 source | Agents connected to that server get the Conquistador MCP tools. | From 0.4.0; checked with Executor 1.5.40 and 1.6.8 |
| `conquistador connect` | Checks analytics, ads, CRM, email, and other capabilities through the legacy Executor interface. | From 0.3.0; v2 compatibility remains open |

## Add Conquistador to Executor 1

<Note>
  From 0.4.0.
</Note>

1. Run `npx @forsvn/conquistador@latest` and choose **Executor**.
2. Enter a source name, or keep the default `conquistador` (`--executor-name=NAME`).
3. Confirm the plan.

The installer runs `executor call executor mcp addServer`. Executor asks to approve the change, and the installer says yes for that one change, because you approved it in the review. When Executor is installed but not running, the review says so, and the step starts it with `executor daemon run`. An Executor version without `mcp.addServer` gets the steps to add the source by hand.

Executor 1.5.40 can add a source but cannot remove or replace one from the command line. With that version, `conquistador remove` tells you to remove the source in the Executor app (`executor web`).

Choose this option only for agents that do not get the plugin or a direct MCP config. An agent that has both gets the same tools twice.

## Connect services with `conquistador connect`

`conquistador connect` shows 22 capabilities, for example "read the CRM" or "send email". Each one
is missing, connected, or verified through the legacy interface. For Executor 2, use its MCP
discovery flow; this CLI does not establish v2 provider readiness.

```sh
conquistador connect                    # Show every capability
conquistador connect launch             # Only the capabilities that the launch command uses
conquistador connect add                # Open the Executor web UI to add an integration
conquistador connect verify crm.read --tool hubspot.contacts.search --args '{}'
```

- `verify` runs one read tool and records the result in `~/.conquistador/connections.json`.
- Set `CONQUISTADOR_EXECUTOR_URL` to check one Executor server only.
- Reads run without a prompt. Sends, publishing, and spend need your approval each time.
- Conquistador does not start an Executor daemon by accident.
