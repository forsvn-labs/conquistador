# Define and verify unit economics

Use the user's actual cost and outcome records. State the currency, period, population, and accounting boundary before calculating. Missing inputs remain unknown. The formulas below define arithmetic; they supply no industry benchmark or permission to spend.

## Acquisition and delivery

Keep marketing spend, sales effort, onboarding, and continuing delivery costs separate before combining them. State which costs the question requires. Match an outcome cohort to the costs incurred to obtain it, accounting for the delay between spending and a completed purchase.

| Measure | Calculation | Required qualification |
|---|---|---|
| Cost per thousand impressions | Attributed spend / impressions × 1,000 | Measured impressions and matching spend period |
| Cost per click | Attributed spend / measured clicks | Click definition, duplicates, attribution |
| Cost per lead | Included acquisition cost / eligible leads | Explicit lead qualification |
| Cost per acquisition | Included cost / defined acquisitions | Acquisition event and cost scope |
| Customer acquisition cost | Included acquisition cost / new customers | Customer identity, timing, allocated sales cost |
| Cost per completed task | Included delivery cost / completed tasks | Completion criteria and failed-task costs |

A zero denominator makes a ratio unavailable. Do not return zero cost for an unavailable or unfinished outcome. Show blended and channel-specific costs separately and document attribution rules before adding them.

## Revenue and contribution

Average revenue per user is included revenue divided by the eligible user population. Average revenue per paying user uses paying users as its denominator. State refunds, discounts, tax treatment, and period rather than assuming every gross payment is retained revenue.

Contribution is included revenue minus the variable costs defined for the decision. Specify the included costs, such as delivery, fees, fulfillment, support, and returns. Cash timing needs a separate schedule even when contribution is positive.

Observed customer value is accumulated contribution for the measured cohort and period. A lifetime estimate extends beyond observed data and must be labeled a forecast. State retention, margin, discounting, and time-horizon assumptions. Do not treat a short cohort's average as a measured lifetime result.

## Efficiency and return

A value-to-acquisition-cost ratio is meaningful only when the value and acquisition cost refer to compatible cohorts and cost definitions. Choose a decision threshold from the user's constraints and evidence. This reference defines no universal healthy ratio.

Payback is the time required for cumulative contribution to cover acquisition cost under the stated cohort model. If it never does within the observed window, report that fact. A forecasted payback date remains a forecast.

Return on ad spend divides attributed revenue by ad spend. It does not establish profitability or incrementality. Return on investment compares the defined net return with the included investment; show what each term includes. Incremental return needs a defensible counterfactual, not a before/after comparison alone.

## Retention and reactivation

Define who had an opportunity to return, the return event, and the window. Separate reactivated users from new users and distinguish a return visit from renewed useful activity or payment. Include reactivation and support costs when comparing paths.

For recurring revenue, state starting-cohort revenue and the changes from expansion, contraction, and churn. Exclude new-customer revenue from the existing-cohort retention measure. Explain joins and missing records before reporting a percentage.

## Product-specific units

A connected wallet is not necessarily a unique person, an active user, or a paying customer. Locked asset value is not retained revenue. State the actual event and unit for products whose usage records differ from customer identity. Do not assign generic fee or retention rates to them.

## Scenario and budget review

Start with the observed baseline. Change a stated input at a time or explain coupled changes. Show the result under plausible user-supplied ranges and identify the assumption that controls the decision. A goal worked backward through conversion assumptions is a scenario, not a required spend plan.

Return a table of metric, formula, inputs, source, period, uncertainty, and decision implication. Keep unavailable values visible. Use [benchmark review](benchmarks.md) for external comparisons. Spending and changes to billing remain human-owned.
