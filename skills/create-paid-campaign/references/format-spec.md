# Verify the selected ad format

Resolve one network and placement before drafting. This file supplies the check
procedure, not a timeless table of platform caps. Use current supplied specification
or account evidence. Record source, date, region, placement, and account constraints.
Without that evidence, produce provisional components and mark launch checks open.

| Network | Component inventory to verify |
|---|---|
| Meta | Primary text, headline, description, visual dimensions, placement visibility, CTA menu, destination |
| Google Ads RSA | Headline and description lengths/counts, display paths, final URL, permitted combinations and pinning |
| TikTok in-feed | Ad text, video/audio specification, display identity, CTA, disclosure |
| TikTok Spark Ads | Authorized post, inherited caption/identity, usage period, audio and disclosure |
| LinkedIn Sponsored Content | Intro, headline, description, image/document, CTA, landing page or Lead Gen Form |

For every component record its exact value, measured length or dimensions,
applicable requirement, and pass/fail/unverified result. Distinguish submission
limits from observed truncation in a placement preview. Never claim that a short
headline is always visible across all placements. Keep essential qualifications
in the visible message or use another supportable claim.

For RSA, inspect allowed combinations so one asset cannot contradict another.
Asset count follows verified platform requirements and available evidence, not a
separate quota of headline angles. For video, specify captions and a still or
poster fallback plus reduced-motion delivery. Check silent comprehension as well
as audio. For Lead Gen Forms, check the actual fields and onward behavior.

Recheck after voice edits or polish. Retain the evidence and changed-component
record with the format result. Read policy-floor.md for claims and permissions.
Platform validation is a required input to launch readiness, not launch authority.
