# Assemble evidence for the paid test

Read available product, audience, brand, campaign, and performance artifacts first.
Do not start a new research project when the supplied record answers the decision.

Create an input table with fact, source path, date, permitted use, and uncertainty.
Include the offer price and terms, user task, destination behavior, supported
capability, exclusions, and outcome event. Customer wording requires permission
and its actual context; internal research is not automatically publishable proof.

For every proposed claim, create a claim_list entry linked to available_proof.
Record the population, period, measurement method, and exact scope the evidence
supports. Product behavior can support a factual capability claim without a
customer statistic. Remove claims that exceed the evidence rather than adding an
unrelated named source to satisfy a specificity count.

Write the buyer's unresolved question and the product fact that could answer it.
Do not invent a hidden emotional motive, a required belief sequence, proprietary
mechanism, urgency, or superiority over all alternatives. Explain how the product
performs the task using verified steps and limitations.

Turn the uncertainty into a test statement: changing this component is expected
to change this qualified outcome for this eligible audience. List the controls,
competing explanation, observation requirement, and result that would reject the
hypothesis. Composer receives this record; critic checks that the output stays
inside it. Missing evidence becomes a question or a draft limitation.
