# Draft headlines from the decision brief

Use the headline to help the intended reader recognize the offer and decide whether to continue. A familiar sentence pattern is optional; it cannot supply a missing product fact.

Start with the requested surface, audience situation, and the most relevant supported fact. Draft alternatives only when they emphasize a different useful reason to read, such as the task supported, a specific capability, or an actual change in the product.

Read each headline without the body copy. Check whether it implies a guarantee, universal compatibility, a time claim, or an exclusive advantage that the evidence does not support. Qualify or rewrite misleading wording rather than hiding the limit below the first screen.

Then read the headline with the body. The next section must deliver the information the headline promises. Avoid curiosity gaps that delay the facts needed to evaluate the offer.

Return each candidate with its intended emphasis, supporting fact, and tradeoff. Recommend the candidate that fits the brief. If the user wants an experiment, state the question it tests without predicting a winning conversion rate.

Synthetic example: for a product that compares two CSV files, a candidate can name the comparison task. A headline promising automatic error elimination would exceed that capability. The critic should reject it even if it is vivid or distinctive.

Use [copy review](copy-review.md) as the final check. Generic but accurate instructions can be useful; unsupported uniqueness is not required.
