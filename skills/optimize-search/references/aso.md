# Improve an app or marketplace listing

Use the current listing, product facts, target audience, and requested store or marketplace. Platform names identify the destination; they do not supply a universal ranking recipe.

## Inspect the listing

Record the platform, locale, version, public URL, and supplied export date. Compare the title, description, images, category, pricing, compatibility, and action with the actual product. Mark unsupported claims and missing facts.

Check current official field limits, asset requirements, indexing documentation, and review rules for the selected platform before preparing a submission. Preserve exact technical identifiers where required. If those requirements cannot be verified, return a draft with the affected fields marked pending verification.

## Develop useful alternatives

Choose wording from the task the intended user wants to perform and the product's actual behavior. Explain which fact each title or description emphasizes. Do not assume competitor keywords, keyword repetition, or a fixed word count guarantees ranking.

For images or video, show the relevant product state and the action or result a user needs to understand. Label any synthetic illustration. Do not imply that a render proves the interface exists or that a review quote is authorized.

## Evaluate reviews and comparisons

Group supplied reviews by concrete issue, version, and context. Keep complaints, praise, feature requests, and unavailable information distinct. Review volume and recency can be observed, but this method assigns no private platform weight or universal review-count target.

Draft responses that address the actual issue without exposing private user details. Any solicitation, incentive, or response must follow the destination's current rules and the user's authority. Do not manufacture reviews or imply endorsement.

## Measure the proposed change

Define the useful event, denominator, audience, and comparison window. Separate store views, installations, activation, purchases, and retention. Record traffic or product changes that could explain a difference. A listing edit does not establish causality by itself.

Return finished listing copy or concrete asset recommendations, supported facts, alternatives, current constraints, proposed measurement, and unresolved submission requirements. Publishing and external replies require approval. No installed benchmark or factor ranking is evidence of expected lift.
