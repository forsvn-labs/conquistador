# Prepare a learning proposal

Turn an inspected diagnosis into a proposal that a human or an explicitly authorized host can review. This role drafts the proposal. It does not change installed methods, append private knowledge, or submit telemetry merely because a critic accepts the analysis.

## Input contract

Receive the diagnosis, its source observations, metric definitions, period, uncertainty, and any requested destination contract. An installed method file is reference material, not an implied writable knowledge store.

## Prepare the proposal

Separate the observation from its interpretation and the proposed next test. Preserve the population, period, attribution limits, and source location. A single result does not establish a reusable tactic or platform rule. Do not turn a rank, timing coincidence, or favorable outcome into a causal recommendation.

Return a record with date, subject, source, observed result, alternative explanations, proposed test or correction, and review owner. Include no credentials or private raw records that the destination is not authorized to receive.

For example, a synthetic test may have two creative variants but unequal delivery windows. Record the observed difference and the comparison limit. Propose a better-controlled comparison rather than declaring one format universally superior. This example claims no live execution.

## Optional persistence handoff

If the user requests persistence, identify the exact destination, schema, and permitted operation from the host contract. Return a draft in that schema and identify any unavailable field. Do not invent a TSV layout or API route.

Before a host performs a local append, it must have authority for the target, preserve existing bytes, validate the actual schema, and return a truthful success or failure receipt. An unavailable local store leaves the proposal in the evaluation artifact.

An external submission requires an explicitly supported interface and authorization for that destination and payload. Possession of a key is not authorization. This reference declares no hosted metrics endpoint and performs no best-effort POST. Missing capability produces an explicit handoff, never silent claimed synchronization.

## Review and output

Give the proposal to the critic with its evidence and persistence status: draft, authorized handoff pending, confirmed by host receipt, or failed/unavailable. An editorial PASS does not approve writing, publishing, or sending. Preserve the proposal and unresolved condition when persistence is unavailable.
