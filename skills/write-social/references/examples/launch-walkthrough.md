# Launch walkthrough: review-ready bundle

Synthetic Product Hunt launch plan for a fictional import-review product. No launch, outreach,
live verification, observed result or user testimony occurred. Copy needs real product support
and task-local account checks before use.

## 1. Fit and constraints

Goal feedback. The operator can staff a two-hour review window of their choosing; that duration
is a fictional capacity budget, not a platform advantage. Gallery screenshots and a reply owner
are required dependencies. Missing assets defer action readiness while drafting can continue.
Load §0 fit/defer, §1 opening choices, §2 checks and §4 anti-patterns.

## 2. Launch bundle

- Identifier: "Row Review".
- Descriptor: "Inspect rejected import rows before you retry them."
- Maker comment: "We work on Row Review. It collects rejected rows so you can inspect the error,
  correct the missing field and retry those rows. The demo shows that sequence. Which error
  information would you need before deciding whether to retry?"
- Gallery plan: show rejected row, error explanation, correction and retry result. Use synthetic
  records visibly labeled as demo data. Assign capture, caption and accessible-text ownership.
- Notify draft: "Row Review's import demo is ready to inspect. If import recovery is part of
  your work, the demo shows the rejected-row workflow. We would value a specific missing step."
- Cross-post draft: "An import fails. Do you retry the file or inspect the rejected rows first?
  This demo walks through inspection, correction and retry. The supplied demo link has the steps."
- Reply plan: answer workflow questions within the staffed window; log unsupported capability
  requests without promising them. Name the next owner when the window ends.
- Follow-up plan: summarize recurring questions after the declared observation window. Distinguish
  actual questions from interpretation; choose one explanation to revise in the next bounded test.

Channel metadata + compliance records exact counts, intended destination, current listing/media
requirements to verify, source/date of supplied checks, missing assets and action authority.
No fixed tagline cap, launch hour, vote request or rank promise is assumed.

## 3. Narration and review

Legibility uses Packed with the actual method_updated, last_verified null, verifier none,
status draft and pack_verified none. Cite §1 for the task opening, §3 for qualified workflow
questions, §5 for the bounded explanation test, §6 for staffed timing and §7 for the demo path.
The method choice is not evidence that the channel rewards it.

Why this works cites the fictional brief and the visible retry sequence; it is a synthetic
product-fit bet. A real task without those facts uses Absent. Place both blocks after Channel
metadata + compliance and before Critic verdict.

Guard checker reviews identifier, descriptor, maker comment, gallery, notify, cross-post and
reply/follow-up plan. Return pending facts explicitly. Known defects use REVISION_REQUIRED,
then GUARD_FAIL if unresolved within the bounded loop. The critic uses evidence and delivery
checks; it cannot approve sending or publishing.

## 4. Handoff and measurement

Return a durable launch artifact using the local artifact convention, with the complete bundle,
status done_with_concerns while material checks remain, production owners and pending action gate.
For a Reddit adaptation, create a separate artifact with community fit, permitted lane, disclosure,
standalone answer, flair checks and reply capacity. Do not copy the listing unchanged.

Before activation, choose the comparison, denominator, window and stop rule for a gallery
explanation test. Candidate outcome: qualified workflow questions among attributed demo visits,
if both can be observed under a consistent definition. Rank and votes do not prove comprehension
or causality. Pass the plan and unknowns to measurement; do not create observation rows.
