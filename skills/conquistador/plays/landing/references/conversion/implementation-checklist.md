# Planned acceptance and actual evidence

Use this checklist only for the requested implementation scope. Each row must carry planned,
passed, failed, or unrun, plus evidence when executed. A brief alone cannot pass implementation tests.

| Area | Acceptance question |
|---|---|
| Claims | Do deployed words match approved evidence and qualifications? |
| Assets | Are real assets permitted, and are missing assets clearly handled? |
| Action | Does each label describe its actual destination and commitment? |
| Forms | Are collection purpose, validation, result states, and recovery implemented? |
| Choice | Are refusal, cancellation, costs, and conditions understandable where relevant? |
| Reading | Do heading and content order work across the selected layouts? |
| Access | Can the task be completed with the selected keyboard and assistive checks? |
| Motion | Is essential meaning available without motion or hover? |
| Data | Does collection match the approved data-handling scope? |
| Measurement | Are event definitions and test limitations recorded without invented results? |
| Handoff | Is the target stack verified or explicitly unresolved? |

Link actual local checks, screenshots, or reports only when they exist. Never label an example,
planned check, or generated layout as a live user study. Keep publication and external action behind
the operator's scope and authority, separate from approval of the copy.
