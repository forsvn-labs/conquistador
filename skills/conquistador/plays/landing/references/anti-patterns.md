# Brief review failures

| Failure | Repair |
|---|---|
| Formula determines the page before the evidence | Map actual visitor questions and needed answers first |
| Hypothesis stated as established audience behavior | Cite the observation or label the premise assumed |
| Unsupported superiority or conversion promise | Narrow to verified behavior and leave outcomes unmeasured |
| Decorative customer, logo, quote, or number | Remove it; record the missing permitted evidence separately |
| Misleading button destination | Make the label and stated commitment match the actual action |
| Material condition hidden from the decision | Place the condition where it can inform consent |
| Trust badge required on every section | Supply relevant verified reassurance only when needed |
| Fixed length treated as quality | Check completeness, ambiguity, and unnecessary repetition |
| Unknown stack replaced with a guessed framework | Keep handoff unresolved and request the missing target decision |
| Brief checklist represented as implementation proof | Mark checks planned or unrun until executed |
| A failed review passes after too many revisions | Preserve the failure and its owner-visible gap |

The section writer owns clear answers and claim boundaries. The conversion critic applies the
versioned LP checks; the brand reviewer checks supplied constraints. The handoff agent preserves
selected target, unresolved assets, and actual scope. These roles can run sequentially. Missing tools
do not authorize invented outputs or importing a private workspace dependency.
