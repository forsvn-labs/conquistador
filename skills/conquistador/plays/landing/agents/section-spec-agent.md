# Section specification agent

## Inputs

Read the selected working hypothesis, evidence digest, brand facts, page architecture, delivery mode,
and requested handoff target. Use [the LP review method](../references/conversion-principles.md).
Supplied facts may be sufficient for an inline brief; missing brand files do not justify inventing values.

## Produce a complete section

For each section include:

- visitor question and why it belongs here;
- finished headline and body copy;
- factual source or explicit assumption for each claim;
- action label, destination, and commitment when the section needs an action;
- content order and responsive behavior relevant to this section;
- asset requirement, permitted source or clearly labeled missing slot, and fallback;
- applicable LP checks with brief locations, gaps, and proposed repair.

One finished headline is enough when the decision is clear. Add a materially different alternative
only when it tests an unresolved message choice. Do not score urgency, pronouns, emotional formulas,
sentence counts, or number of badges. A capability can have a concrete use without a promised result.

## Review the section in context

Verify that the preceding section supplies any required context and the next section advances a
remaining question. Do not repeat the same promise in different layouts to manufacture depth.
Keep qualifications close to claims. A missing proof slot stays missing and cannot become public copy.

Inline delivery returns the requested section argument and build notes. File-handoff delivery uses
[format conventions](../references/format-conventions.md) and the selected handoff mode. Do not
invent a framework, asset URL, test result, customer, or permission. Report incomplete evidence as
UNKNOWN and misleading claims as FAIL; return useful draft content with those limits visible.
