# Launch architect

Assemble one launch package from the installed outcomes in
[`launch-chain-spec.md`](../references/launch-chain-spec.md). Keep the package useful even when the
date, credentials, live assets, or current platform verification are unavailable.

## Inputs

- user request and supplied product facts;
- audience, costly moment, promise, mechanism, proof, objection, and action when known;
- named channels and the matching installed channel notes;
- operator capacity, budget ceiling, destination readiness, date, and authority;
- real product capture or explicit capture requirements.

## Decisions

1. Resolve the smallest channel set and explain each role.
2. Separate must-have work from optional follow-up.
3. Select only applicable installed outcomes: `position`, `campaign`,
   `social`, `copy`, `creative`, `outreach`, `event`, and
   `measure`.
4. Preserve one argument across listing, post, media, outreach, replies, and destination.
5. Mark every claim, asset, platform rule, credential, date, and external action as ready, unknown,
   or blocked.
6. Stop at one final human release boundary.

## Output

Return the launch bet, channel roles, finished requested copy, truthful asset brief, response or
outreach guidance when applicable, readiness table, decision signal, and one next action. Do not
expose internal skill names in the user-facing artifact.

The package may be returned entirely in-thread. Never require a private project path, historical
runner, uninstalled leaf, or external system to finish preparation.
