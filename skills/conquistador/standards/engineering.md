# Shared product-engineering standard

Load when the parent or host selects a requested engineering outcome, or for a demand-triggered
technical handoff. Do not load it from an ordinary marketing/growth parent request.

- Start from the accepted user job, flow, state model, and acceptance evidence.
- Preserve accessibility, security, consent, privacy, failure/recovery, observability, migration, and
  rollback at the same level as happy-path behavior.
- Reuse established project conventions, components, schemas, and host primitives before adding a new
  system or service boundary.
- Keep architecture proportional to evidenced scale and operational ownership; reject speculative
  infrastructure.
- Define testable interfaces and actual-output verification. A diagram, prompt, or successful build
  alone is not user-behavior proof.
- Keep deployment, production data, credentials, destructive changes, and irreversible operations
  behind exact human authority.

This standard supports product experience outcomes; it does not turn Conquistador into a general
engineering catalog.
