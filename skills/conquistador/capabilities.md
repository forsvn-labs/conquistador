# Compact capability map

Use this map privately. Select the smallest outcome or composition that produces the requested result.
Skip a step when accepted context already supplies its decision; never narrate this map.

## Launch or grow this

| User outcome | Primary outcome | Add only when needed | Required finish |
|---|---|---|---|
| Shape an ambiguous initiative | `shape-initiative` | `decision-panel` for consequential contested options | Bounded decision, exclusions, smallest reversible next move |
| Understand a market, customer, offer, or position | `research-positioning` | `knowledge-review` for conflicting sources; `create-brand` for durable identity | Evidence-backed position and decision implications |
| Research content opportunities | `research-content-ideas` | `research-channel` for current platform fit | Ranked source-grounded angles and a first brief |
| Diagnose a growth problem | `diagnose-growth` | `measure-growth` for real baselines | First evidenced break and discriminating tests |
| Prioritize opportunities | `prioritize-opportunities` | `model-growth-funnel` for numeric feasibility | Forced ranking, cut line, reversal evidence |
| Model a growth or revenue target | `model-growth-funnel` | `measure-growth` for observed baselines | Inspectable model, sensitivity, constraints, evidence plan |
| Allocate marketing budget | `allocate-marketing-budget` | `model-growth-funnel` for target math; `plan-campaign` after allocation | Bounded allocation, marginal logic, reallocation triggers |
| Design pricing and packaging | `design-pricing-and-packaging` | `research-positioning` and `knowledge-review` for market evidence | Value metric, package/price logic, validation and migration |
| Research or choose a channel | `research-channel` | `plan-campaign` after the channel role is chosen | Typed evidence, focused recommendation, first test |
| Plan a campaign or launch | `plan-campaign` | Relevant research and creation outcomes | Campaign spine, assets, owners, budget, stop/scale rules |
| Create paid media | `create-paid-campaign` | `brief-creative` for production | Finished ads, creative direction, bounded budget/test |
| Create a run of show | `create-run-of-show` | `plan-campaign` for campaign context | Timed cue sheet, owners, contingencies, follow-up |
| Improve search or answer visibility | `optimize-search` | `write-copy` for revised pages | Technical/content diagnosis and prioritized correction |

## Direct-only engineering outcomes

These outcomes are package-present but outside the default parent route and the v1 marketing/growth
usefulness claim. Do not select them as part of an ordinary Conquistador job. A host may invoke one
directly when the user explicitly requests that engineering outcome.

| User outcome | Primary outcome | Add only when needed | Required finish |
|---|---|---|---|
| Map a product journey | `map-user-flow` | `research-positioning` for unresolved user evidence | Screens, transitions, states, recovery, validation |
| Specify an interface | `brief-product-ui` | `map-user-flow` when the accepted flow is absent | Traceable components, tokens, states, accessibility, handoff |
| Architect a demanded system | `architect-software-system` | Private service-extraction method when justified | Bounded architecture, interfaces, risk, acceptance |
| Build an iOS experience | `build-ios-app` | `map-user-flow` and `brief-product-ui` for product truth | Native implementation with simulator proof and release boundary |
| Build a web experience | `build-web-app` | `map-user-flow` and `brief-product-ui` for product truth | Responsive accessible implementation and browser proof |
| Write technical documentation | `write-technical-docs` | Architecture/implementation evidence | Accurate reader-tested documentation with verification |

## Learn from these results

| User outcome | Primary outcome | Add only when needed | Required finish |
|---|---|---|---|
| Learn from aggregate growth results | `measure-growth` | `diagnose-growth` for the first break | Keep/drop/test decision and bounded learning proposal |
| Evaluate actual paid results | `evaluate-paid-campaign` | `measure-growth` for business-level synthesis | Cell diagnosis, attribution limits, bounded decision |
| Evaluate a sent outreach cycle | `evaluate-outreach` | `write-outreach` after the next-batch decision | Delivery/qualified-reply diagnosis, compliant next batch |
| Evaluate actual short-form output | `evaluate-shortform` | `create-shortform` after learning is accepted | Actual-output review, confounders, bounded next brief |
| Audit a marketing package | `audit-marketing` | Relevant outcome only for accepted fixes | Severity findings, preserved work, human-review readiness |
| Review a consequential artifact | `fresh-eyes-review` | Domain outcome for criteria, never as sole producer/reviewer | Honest independence status, sparse defects, recheck boundary |
| Audit the facts behind a claim | `knowledge-review` | `decision-panel` when credible positions still conflict | Authority/freshness/uncertainty matrix and recheck trigger |
| Resolve a consequential decision | `decision-panel` | `knowledge-review` for source conflicts | Chosen position, dissent, uncertainty, criteria, reversal evidence |

For a multi-stage request, load the exact file in `workflows/` only when two or more outcomes must
compose. Those files are prose-composition sources, not playbooks. The first compounding playbook is
`content-intelligence-loop`: composition-only / release-required-unimplemented until an authorized
judgment response and runner trace exist. Its one social branch is
`research-content-ideas` → `write-social` → `fresh-eyes-review` → human verdict boundary → optional
action handoff → `measure-growth`, composed from the exact files named in
[workflows/content-intelligence-loop.md](workflows/content-intelligence-loop.md). Preserve one
decision spine across audience, costly moment, promise, mechanism, proof, objection, action, primary
signal, and decision date. Return one coherent terminal Review Packet, not separate skill reports.
