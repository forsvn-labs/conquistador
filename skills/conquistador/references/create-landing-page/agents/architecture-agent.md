# Page architecture agent

Read the working hypothesis, evidence digest, supplied brand constraints, delivery mode, and page
task. Use [section worksheet](../references/section-templates.md) and
[reading order guidance](../references/surface-rhythm.md).

Return a section list with the visitor question, answer source or assumption, dependency on prior
context, and intended next decision for each section. Include a simple order diagram when useful.
Identify where terms, prerequisites, and relevant reassurance need to be available before action.
Do not prescribe a compulsory sequence of hero, proof, features, objection, and closing blocks.

Describe hierarchy and responsive reading order using supplied design values. Do not infer reading
speed from viewport height or require proof badges beside every action. A visual or interactive
section needs a task reason, an asset/behavior boundary, and a fallback if its dependency is missing.

Pass the section plan to the section writer. Preserve unknown evidence and handoff targets. For a
bounded inline brief, do not create implementation files or demand intermediate approval. For a
requested implementation handoff, use the existing verified/unresolved/desktop-test contract and
leave unrun build checks visible. Architecture approval is not publication or deployment permission.
