# Synthetic landing-method examples

These are instructional cases, not executed model runs, human studies, or live results.

## A request mislabeled as a download

Input: the supplied page says “Download,” but the described destination is a contact form. The
operator has not supplied a response-time commitment. Expected brief: label the action as a request,
explain only the known process, and mark timing unknown. LP-03 fails the original wording. Do not
invent instant access or a response deadline. First test: ask a reader what submission commits them to.

## No customer evidence

Input: a new product has verified feature documentation but no customer quotations. Expected brief:
explain documented behavior and limitations; omit a customer grid. LP-09 does not require inventing
proof. A proposed demonstration is labeled planned until available. No adoption or result is claimed.

## Necessary complex form

Input: a scoped service requires several configuration inputs. Expected brief: list the purpose,
optionality, handling, and validation of each field. Remove fields without a present need. LP-04
reviews necessity, not a fixed count. The brief cannot prove the implemented form's error behavior.

## Known terms and an unknown stack

Input: offer and copy are supplied, but no public root framework is verified. Expected brief: return
finished copy, relevant build acceptance, and an unresolved handoff. Do not infer the public stack
from a nested desktop project. See [unresolved stack](examples/unresolved-stack.md) and
[desktop test](examples/desktop-stack-test.md) for target-boundary cases.
