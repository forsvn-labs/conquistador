# Specialist roster

The Conquistador parent uses these roles for assignments that cross GTM capabilities. Each role
combines existing outcome skills, project knowledge, and named composition workflows. These roles do
not replace the commands or create another method library.

| Specialist | Use for | Primary skills | Named workflows |
| --- | --- | --- | --- |
| [Ads](ads-agent.md) | Paid campaign creation and account-ready changes | `ads`, `results`, `budget` | `paid` |
| [Copy](copy-agent.md) | Routing and writing the correct copy form | `copy` plus the channel owner | `gtm`, `landing`, `outbound` |
| [Direct-response landing](dr-landing-agent.md) | Offer-led pages with a complete belief and action path | `position`, `copy`, `creative`, `convert` | `landing` |
| [SaaS landing](saas-landing-agent.md) | Product-led pages for trial, demo, or qualified activation | `position`, `copy`, `creative`, `convert` | `landing` |
| [Data diagnosis](data-diagnosis-agent.md) | Find the first measured break and competing explanations | `diagnose`, `measure`, `funnel` | `plan`, `report` |
| [Campaign data](campaign-data-agent.md) | Event contracts, extracts, holdouts, and money-event readouts | `measure`, `results`, `results` | `paid`, `experiment` |
| [Creative assets](creative-assets-agent.md) | Produce and review a coherent volume of paid or short-form assets | `creative`, `ads`, `video` | `paid`, `series`, `qa` |

Use [specialist team execution](../orchestration/specialist-team.md) for assignment packets,
dependencies, parallel work, integration, and fallback. Use
[connect accounts](../methods/connect-accounts.md) and [stack setup](../methods/stack-setup.md)
when a role needs a missing data or provider interface.

The parent may use one role or several. Do not add a coordinator specialist. The parent coordinates.
Do not add a reviewer specialist when an existing review outcome supplies the judgment.
Public labels in this table are the product-owned roster. Briefs, child titles, and receipts must
use them. Do not invent display names from model prose.

The executable coordinator uses Outcome for unnamed roles and Integration, Review, Correction, and
Final review for its observed stages. These are stage labels, not additional specialist methods.
