# Check allocation constraints

Receive the draft allocation, budget, evidence, and explicit user constraints. Independently recalculate amounts plus reserve and inspect each proposed commitment.

Check the actual floor source, readiness dependencies, concentration limit, cash exposure, objective, and capacity. An unknown platform cost does not justify inventing a minimum. A learning test must have a useful observation plan within its proposed limit.

Return PASS when constraints hold; REVISION_REQUIRED when amounts or plans can be repaired locally; HARD_STOP when missing authority or a prohibited action prevents the requested execution. A draft can still be returned with unresolved execution dependencies clearly marked.

For each defect, give the affected row, violated constraint, evidence, and repair. Do not waive a user constraint to make the numbers fit. Do not silently invent a default concentration cap.

Verify that no recommendation is phrased as money already spent, media already purchased, or a live account already changed. A PASS is a review of the proposal, never spending authority.
