# Conversion diagnosis review failures

Apply these checks with diagnostic-evidence-method.md and conversion-critic-agent.md.

| Failure | Detection and repair |
|---|---|
| Unsupported problem statement | Current/target values lack definitions, population or source. Preserve unknowns and obtain the deciding context. |
| Symptom restated as cause | Candidate repeats the decline without a mechanism or discriminating prediction. State what observation separates it from an alternative. |
| Forced diagram | Extra branches, depth or categories exist only to satisfy a template. Keep the candidate map the evidence needs. |
| Overlap hidden | Shared users, mediation or interaction are counted twice. Link the candidates and report non-additive contributions. |
| False completeness | Analysis claims every cause is covered or fills a residual with guesses. State omitted scope and unknown attribution. |
| Measurement omitted | Analytics definitions or event changes are ignored. Check compatible independent sources before interpreting behavior. |
| Composition mistaken for behavior | Blended rate moves while segment rates remain stable. Calculate population shares and within-segment outcomes. |
| External evidence fabricated | A search is claimed without a capture, or missing evidence is Ruled Out. Preserve unavailable coverage and distinguish event existence from effect. |
| Formula mistaken for causality | An identity allocation is called a root cause. Show interaction and convention, then separate causal evidence. |
| Arbitrary hypothesis form | Literal words or a one-number rule replace falsifiability. Keep prediction, mechanism/unknown, alternative and deciding evidence set. |
| Confirmation from timing | Co-timed change or rate movement is treated as decisive. Check competing explanations and retain Inconclusive when needed. |
| Invented gap shares | Guessed contributions add to 100% without attribution boundaries. Use supported units/bounds or unknown and show residual/interaction. |
| Forced escalation count | Root cause is chosen or rejected because a fixed number of candidates failed. Stop according to evidence and decision needs. |
| Missing data handoff | Deciding data/source/owner or confirming/rejecting criteria are absent. Restore the fields with explicit unknowns rather than invented answers. |
| Lost revision outcome | Diagnosis ends without the requested usable Change/Test revision or its blocker. Carry evidence limits into that handoff. |
| Polish hides FAIL | A polish pass substitutes for a failed evidence check. Return the defect to its owner within the bounded rewrite limit. |
| Contract drift | Phase headers, stable ids, verdict columns or Next Step disappear. Keep the updated artifact contract and flag downstream interpretation changes. |

An inconclusive result with specific deciding data can pass review. Unsupported certainty cannot.
No checklist requires live collection or authorizes external execution. Preserve source rights.
