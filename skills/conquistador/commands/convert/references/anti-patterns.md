# Conversion rewrite failures

Check the diagnosis and the revised page against this list before delivery. The post-launch
evaluation lens has its own list in [landing anti-patterns](landing-anti-patterns.md).

| Failure | Fix |
|---|---|
| A best-practice teardown presented as a measured cause | Label it a heuristic reading; name the evidence that would confirm it |
| The page is blamed before traffic is split by source | Compare conversion by source and device first |
| The headline is rewritten while the first screen still mismatches the ad or email | Fix message match first: same words, same offer |
| Proof removed or blurred in the rewrite | Keep a sourced number exact; put its source and scope in the operator note |
| The rewrite turns a buzzword hero into a literal product description | Start the headline from the visitor's want or pain; the product goes in the subhead |
| Source text, hedges, or a restated audience added to the page | Move sources to the operator note; cut hedges; remove unsupported claims instead |
| Fields cut without checking what sales or onboarding needs | Keep needed fields, or test removal with lead quality as a guardrail |
| Button label hides the real commitment, such as a sales call | Say what happens after the click |
| Several changes tested at once and read as one cause | Ship the unsupported-claim fixes first; test one change |
| A test the traffic cannot finish | Estimate visitors per variant first; test a bigger change or ship on evidence |
| Keep or kill decided by editorial taste | Use the primary metric and guardrails defined before the test |
| An invented benchmark used as the target | Use the page's own baseline; label any outside number as a starting point |

Deployment, experiment activation, and publishing need the owner's approval.
