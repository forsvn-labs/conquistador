# Check consumer adoption

Use for a consumer application or service when the decision depends on activation, repeat use, or acquisition.

## Trace a useful session

Describe the user's starting situation, the first useful result, and the actions required to reach it. Identify permission requests, account creation, waiting, or payment that could prevent completion. Distinguish a completed setup from a result the user actually values.

Define the expected return occasion from the product's use. A monthly task should not be judged against a daily-use target. Record which users had a genuine opportunity to return before interpreting retention.

## Separate product and channel questions

If people arrive but cannot obtain the result, inspect the product path. If eligible people do not arrive, inspect audience access and the message. Do not infer a channel failure from an unusable onboarding flow or product success from views alone.

For a proposed acquisition test, specify the audience, creative claim, destination, useful action, cost ceiling, and measurement window. Use one interpretable change where possible. Record changes in audience or delivery that prevent a fair comparison.

## Decision output

Return the adoption path, observed losses, competing explanations, and the next test. State which observations would warrant product revision, another channel trial, or stopping. Publishing and paid delivery require separate approval.

## Example, synthetic

A planning app gets registrations but few completed plans. Inspect whether users can finish a representative plan before commissioning more promotional videos. If completion improves, measure return use over the actual planning interval before claiming retention improved.

## Limits

Downloads, impressions, and creator anecdotes are insufficient evidence of sustained value. Report the available denominator and missing observations instead of substituting a universal growth threshold.
