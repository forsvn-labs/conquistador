# Opening choices

Use the visible task and the intended reader decision to choose an opening. The filename is
retained for existing links. These are drafting choices, with no performance order or required taxonomy.

Start by writing the complete answer the post will deliver. Identify what the reader needs to
recognize before that answer makes sense. Then draft alternatives that change that entry point,
while keeping the body, claim scope, offer, and intended action comparable.

| Choice | Use when | Draft check |
|---|---|---|
| Show the task | The audience can recognize a concrete action or obstacle | Name the object and action; show the relevant screen or step when media helps |
| Compare decisions | The reader must choose between plausible options | State the tradeoff, conditions, and cost of each option without inventing a losing opponent |
| Present bounded evidence | Supplied evidence changes a decision | Name the source, scope, denominator and limitation; separate an example from an observed result |
| Give the answer | The reader needs a usable instruction or conclusion | Put the answer first, then explain when it applies and how to use it |
| Show another person's reaction | The product makes a visible result that can change a doubter's mind | Name the other person and their doubt or refusal, show them the result, then show the changed mind. If you cannot name both the person and the conflict, use another opening |

Use the reaction opening only for a real, consented story. Otherwise label it as a scenario; never
present an invented reaction as a customer story.

Other openings are allowed when the author explains the reader need they address. Do not add
credentials, invented customer language, delayed reveals, or a fixed timing target to satisfy a label.

## Draft and production checks

For each variant record the exact opening, reader decision, body passage that delivers it, and
what differs from the other variant. Reject a promise the supplied evidence or body cannot support.
A repeated opening with synonyms is not a useful comparison.

For video, specify the first visible action, spoken line, caption and audio needs. Check whether
someone can understand the task with sound off and whether speech adds information rather than
competing with the image. Set timing from the actual reading, demonstration and production needs.
For text, read the opening with the next paragraph and remove any setup that postpones the answer.
Check the actual intended preview when supplied; otherwise record preview behavior as unknown.

## Bounded test

Select one opening difference and one observable outcome from the task's pack §3. Define the
eligible audience, denominator, window, comparison and stop rule before use. Keep the offer and
CTA constant where feasible. Without comparable observations, return a test plan, not a winner.

## Synthetic example

A fictional task helps an operator find a failed import. No customer quote or result is implied.

- Task opening: "Find the first rejected row in the import log." Show that row and its error.
- Decision opening: "Retry the file or fix the row? Check whether the failure is temporary first."
- Answer opening: "Correct the missing account ID, then retry the rejected rows." Show the edit.

The body explains the check and retry boundary. The handoff includes the screen capture needed,
caption text, exact CTA path, production owner and unresolved account constraints. No sample
counts, retention lift or platform advantage are claimed.
