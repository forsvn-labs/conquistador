# Generate angles from reader decisions

The filename remains for existing local references. The method uses the campaign's
actual reader tasks, unresolved decisions, and permitted evidence. It does not
assign people to a universal progression or derive copy from an emotion matrix.

## Build a decision record

For each relevant audience situation, record the task underway, the decision the
reader must make, what is already known, what is uncertain, constraints, and the
source. Use observed questions, product behavior, consented customer wording, or
the supplied brief. Mark inferred context explicitly. Do not invent proportions
of an audience at different levels of knowledge.

Select a useful information gap the campaign can answer. A pillar groups related
questions that share a product capability or evidence requirement. The same reader
can have several independent questions; completing one does not advance them to
a compulsory next stage.

## Produce a candidate angle

Write a one-sentence content promise that helps resolve the decision. Specify the
evidence it will show and the next action available after reading. Choose an
opening that introduces that actual information: a task description, demonstration,
comparison with supported limits, or answered question. These are options, not a
fixed set of hooks to fill.

Generate an alternative only when it changes a meaningful premise, question, or
presentation. Record what changes and what stays fixed. If there is no evidence
to support another useful angle, return fewer candidates with the gap explained.
Do not add an emotional claim or an unsupported statistic to make the bank larger.

## Select work

First reject candidates with unsupported claims, no relevant reader decision,
missing permission, or no feasible way to present the evidence. Then compare
remaining candidates by decision importance, evidence readiness, channel feasibility,
production effort, and what the experiment can teach. Explain tradeoffs instead
of relying on a total score to cure a blocker.

Keep the Score column as an ordinal priority such as 1, 2, or deferred, with a
reason. It is not a /25 prediction or a mandatory keep threshold. Limit active
angles to actual production and review capacity. Informational content is valid
when it answers the task; provocation and emotional pressure are not required.

## Angle bank compatibility

Preserve the table keys where downstream prose expects them:

| # | Angle | Hook | Stage | Trigger | Score | Class | Pillar |
|---|---|---|---|---|---|---|---|
| ID | Content promise | Opening choice | Free-form reader task/context | Observed event or question, or unknown | Ordinal priority | Intended use with evidence | Parent pillar ID |

Attach Evidence, Decision, Next action, Changed component, Controls, and Rejection
condition for each selected row. Class can describe search, sharing, conversation,
or reference use, but it does not assert reach or algorithm preference. If old
input uses fixed stage or emotion labels, request or infer the underlying task
from its actual evidence; preserve unknown when that evidence is absent.
