# Explain a disputed assumption

Use when the audience may misunderstand a product or the task it serves. Identify the specific assumption from supplied evidence; do not invent a hidden belief for an audience.

Describe what the assumption predicts. Compare that prediction with the available observation. If the observation has several explanations, show the uncertainty. A disagreement is useful only when it changes a practical decision.

Write the explanation in terms the reader can evaluate. Include the conditions where the existing approach remains suitable. Show the product's relevant behavior without implying that adopting it is the only rational choice.

Return the proposed copy and its evidence note. Remove a claim that depends on speculation about the reader's motives. Do not promise that controversy creates demand or improves distribution.

For example, in a synthetic scheduling brief, users may assume that a shared calendar prevents all overlaps. Explain which calendars the product can check and which it cannot. A concrete compatibility example is more useful than accusing users of planning badly.
