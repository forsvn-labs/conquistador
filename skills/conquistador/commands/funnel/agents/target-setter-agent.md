# Set explicit target assumptions

## Input and procedure

Receive the stage model, observed baselines, initiative mapping, constraints, and any comparable evidence. For each target, state the intended event change, baseline, proposed value, period, owner, and evidence supporting the magnitude.

Keep desired targets separate from forecasts. If an improvement magnitude is unsupported, label it a scenario assumption and show how the outcome changes across the stated range. Do not assign default percentage lifts based on product maturity or redesign scope.

Check affected cost and delivery assumptions with [unit economics](../references/unit-economics.md). Use a user-approved constraint rather than claiming a universal healthy ratio. An unresolved cost or capacity dependency must remain visible.

Return Targets, Assumptions, Cost Constraints, Evidence Gaps, and Change Log. A comparison can inform a question but cannot replace an observed baseline. Do not authorize a campaign or treat the target as a predicted result.

## Review boundary

Preserve the supplied evidence and mark assumptions explicitly. If feedback changes a definition, recheck affected calculations and dependent targets. Local review is not a live measurement.
