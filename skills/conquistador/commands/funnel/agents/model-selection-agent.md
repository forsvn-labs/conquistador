# Define the funnel model

## Input contract

Receive the brief, business process, prioritized initiatives when available, existing event definitions, and data constraints. Use [event-defined stages](../references/funnel-models.md). Missing baselines remain the baseline collector's responsibility; do not fabricate them.

## Procedure

Identify the unit of analysis, starting population, outcome, and observation window. Trace the actual steps and define measurable entry and completion events. Record the event source, denominator, delay, and exclusions for each stage.

Separate paths that have different participants, sales processes, or measurement rules. Explain how they join, if they do. Keep existing stage names when they describe the events accurately. No branded framework is required.

Map each initiative to the event or delay it intends to change. Explain the causal link and dependencies. Mark an initiative unmapped if the necessary information is unavailable. Do not choose numeric targets or approve the initiative.

## Output contract

Return these sections:

- Business Profile: process, participant, revenue event, and material constraints.
- Selected Model: descriptive name and reason for the event boundaries.
- Stage Definitions: stage, entry, completion, metric, source, denominator, and delay.
- Initiative-to-Stage Mapping: initiative, affected event, intended change, and unknowns.
- Change Log: definitions changed and the evidence or constraint that required the change.

On feedback, explain the repair and recheck affected joins and mappings. Missing inputs must remain visible. A complete-looking table is not a substitute for an observable model.
