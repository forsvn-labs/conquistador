# Knowledge review

Check that a decision rests on credible, current, and honestly uncertain evidence. The full method
lives in [knowledge review method](references/knowledge-review-method.md); this front door shows the
arc.

## Clarify what is being claimed

State the factual claim or decision the review must support, exactly as it will be used. Enumerate
the sources and data the work currently leans on, including uncited dependencies. Distinguish
observed evidence, reasonable inference, and assumption before judging any of them.

## Assess each source

For every source and claim, record:

- authority: primary or secondary, provenance, perspective, and known bias;
- freshness: an explicit date or how current this category of claim is;
- uncertainty: confidence, sample, and what could change the finding;
- provenance: which tool, route, or reviewer supplied it — see
  [review evidence scope](references/provenance.md) for recording inspected sources and access limits.

An unavailable source is missing data, never zero.

## Build the contradiction matrix

Follow the [contradiction protocol](references/contradiction-protocol.md). For each key claim, put
sources as rows: what each asserts, its authority, date, and uncertainty. Mark every direct
contradiction explicitly so conflicts stay visible rather than merged; classify them (data, causal,
scope, freshness) and count repetition as one origin.

## Resolve

Reconcile conflicts by weighing authority × recency × causal plausibility — never by voting: no
counting or averaging sources. Label the resolved position with its confidence and record why each
loser lost. Preserve real dissent instead of erasing it.

## Verify the resolution honestly

When a separate provider, model family, reviewer context, or evidence tool is available, give it the
claim table without the first resolver's conclusion and record which separate route checked it. Only
call the result independent when a separate context actually ran.

Without that capability, run the [sequential fallback](fallbacks/sequential.md): its counter-read
pass constructs the strongest evidence-led case against the resolution and labels the result as a
single-context fallback, never independent corroboration.

Track which source or tool produced each item. Exclude irrelevant evidence from the active claim table
with a reason; never delete source material or other work without explicit authority.

## Surviving unknowns and recheck trigger

List what remains unknown and set a recheck trigger per unknown: a date, event, or condition when the
claim must be verified again. Do not let an unknown silently age into a fact.

## Grade the review before delivery

Score the finished review against the [review rubric](references/review-rubric.md), which enforces
the required review obligations: sources are never fabricated or padded (`H-KNOW-SOURCE`), contradictions
are surfaced rather than averaged away (`H-KNOW-CONFLICT`), and a dated or event-based recheck
trigger is always set (`H-KNOW-RECHECK`). A worked (fictional) walkthrough of the deliverable shape:
[activation claim audit example](references/examples/activation-claim-walkthrough.md).

## Scope

This reviews knowledge, sources, and factual claims—not code. Do not use it to review an
implementation, a diff, or a codebase; use a code-review path for that. Keep the review proportional
to the decision and never fabricate, pad, or simulate sources. Its resolution informs a human decision
and does not approve publication, action, or release.
